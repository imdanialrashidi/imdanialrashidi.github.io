## Why this matters

The deploy pipeline (`deploy.yml`: checkout → `ci-install.sh` → `npm run
check` → `npm run build` → Pages artifact) has been live for months, and the
SEO pass (search-shaped titles, `@graph` JSON-LD, GSC verification tag) is
committed — but no evidence in the repo shows anyone ever checked what
production actually serves. The cheapest high-assurance item available is a
read-only sweep: real 200 with custom HTML (not a Jekyll fallback), valid
sitemap/robots, fetchable OG image, honest 404 status, and the GSC tag
present in served HTML. Any failure here means CI is green while the public
site is broken — exactly the gap this plan closes. This promotes the
long-standing backlog item "post-deploy live verification" into an executable
check. It does NOT set up monitoring or CI smoke (deferred — see maintenance
notes); it produces one verified snapshot plus a report.

## Steps

### Step 1: Homepage serves custom HTML, not a fallback

```sh
curl -sS -o /dev/null -w "home:%{http_code}\n" https://imdanialrashidi.github.io/
curl -sS https://imdanialrashidi.github.io/ | grep -c "Software & Product Builder"
curl -sS https://imdanialrashidi.github.io/ | grep -c "google-site-verification"
```

**Verify**: status `200`; both content counts ≥ 1. (First proves Pages serves
the Actions artifact; second proves it's THIS site; third proves the GSC tag
shipped.)

### Step 2: Crawler surface — sitemap, robots, OG image, favicon

```sh
for p in sitemap-index.xml robots.txt og-default.png favicon.svg .nojekyll; do
  printf "%s:" "$p"
  curl -sS -o /dev/null -w "%{http_code}\n" "https://imdanialrashidi.github.io/$p"
done
curl -sS https://imdanialrashidi.github.io/sitemap-index.xml | grep -c "sitemap"
```

**Verify**: every status is `200` and the sitemap grep count ≥ 1. Note: if
`robots.txt` is absent (no `public/robots.txt` in repo — check with
`ls public/robots.txt` locally first; if the file doesn't exist locally, a
404 in prod is EXPECTED, not a failure — record it as such).

### Step 3: Every route returns 200 with its own title

```sh
for p in about now contact work work/fast-english work/noveno work/elsa-hamrah work/isbatab work/mobile-khorsandi work/php-ielts-house; do
  printf "%s:" "$p"
  curl -sS -o /dev/null -w "%{http_code}\n" "https://imdanialrashidi.github.io/$p"
done
curl -sS https://imdanialrashidi.github.io/work/noveno | grep -c "og:type.*article\|og:type\" content=\"article"
```

**Verify**: all ten statuses `200` (no trailing slashes per
`trailingSlash: never`); the case-study OG-type grep ≥ 1. (Title-uniqueness
across pages is already guarded locally by `tests/seo-metadata.test.mjs`;
here you only prove routability.)

### Step 4: 404 is honest

```sh
curl -sS -o /dev/null -w "missing:%{http_code}\n" https://imdanialrashidi.github.io/work/does-not-exist-zzz
curl -sS https://imdanialrashidi.github.io/work/does-not-exist-zzz | grep -ci "404\|not found\|go home"
```

**Verify**: status `404` (not a soft-200) and content grep ≥ 1 (editorial 404
with recovery links, per `src/pages/404.astro`).

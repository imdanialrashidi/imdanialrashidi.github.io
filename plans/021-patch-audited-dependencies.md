## Why this matters

`npm audit` at the audit commit reports **10 vulnerabilities (1 critical, 8 high,
1 moderate)** against the pinned build dependencies. The critical hits `astro`
itself (`<7.2.8`); highs include `sharp`, `undici`, `js-yaml`, `devalue`,
`fast-uri`, `http-cache-semantics`, `source-map-js`, `svgo`. These are
build-time (not visitor-runtime — the shipped site is static HTML), but they
are reachable in CI on every push: `js-yaml` parses content frontmatter,
`undici` is Node's fetch, `sharp` processes every responsive image. The prior
"0 vulnerabilities" verdict (plans/README backlog, audit at `29d0bde`) is
stale — advisories were published (or became visible via the canonical
registry) since. Fixes exist inside the already-declared caret ranges
(`astro ^7.2.4` → `7.3.6`, `sharp ^0.35.3` → `0.35.5` both verified on the
registry at audit time), so no major bump or code change should be needed.

### Step 2: Non-breaking fix first

Run `npm audit fix --registry=https://registry.npmjs.org` (no `--force`).
Then re-run the audit from Step 1.

**Verify**: `npm audit` output recorded. If critical+high are all gone, skip
to Step 4. If any critical/high remains, continue to Step 3.

### Step 3: Targeted bump (only if Step 2 left critical/high)

Run:
`npm install astro@7.3.6 sharp@0.35.5 --registry=https://registry.npmjs.org`
then re-run the audit. These are inside the existing caret ranges
(`^7.2.4`, `^0.35.3`), so `package.json` ranges may not even change — only
the lockfile resolves upward.

**Verify**: `npm audit` shows zero critical and zero high. Moderate/low
leftovers are acceptable ONLY if `npm audit fix` cannot resolve them without
`--force`/breaking changes — record them verbatim in your final report.

### Step 4: Prove nothing broke

In order:
1. `npm run check` → exit 0, 0 errors (6 pre-existing hints in

modified files must be `package.json` and/or `package-lock.json`, plus
possibly `public/og-default.png` (byte-identical regen is fine; if it
differs, report it prominently and do NOT revert it yourself).
